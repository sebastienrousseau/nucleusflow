# Governance

This document outlines how the NucleusFlow project is governed: decision-making processes, contribution lifecycle, and project leadership.

## Model

NucleusFlow is maintainer-led by [Sebastien Rousseau](https://github.com/sebastienrousseau), who oversees architectural roadmap, release management, and final design decisions.

## Roles

- **Users**: File bug reports, propose enhancements in Discussions or issues, and integrate the library.
- **Contributors**: Submit pull requests, documentation improvements, and bug fixes following the project standards.
- **Maintainers**: Hold commit and release signing authority, enforce continuous integration gates, and steer technical decisions.

## Decision Making

- **Everyday fixes & enhancements**: Proposed through pull requests, reviewed against strict verification criteria, and merged once all CI checks pass.
- **Breaking changes & architecture**: Discussed in issues before implementation. All API evolutions follow semantic versioning.

## Code of Conduct

All contributors and maintainers adhere to the [Code of Conduct](CODE_OF_CONDUCT.md).
